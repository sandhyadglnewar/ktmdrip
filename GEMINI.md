Agent Instructions: KTMDRIP Infrastructure & DeploymentThis document serves as the primary technical directive for building and deploying the KTMDRIP ecommerce platform. All development should prioritize performance, security, and cost-efficiency using the Cloudflare ecosystem.1. Hosting & Deployment (Cloudflare Pages)Framework: Deploy using Next.js (App Router) or Remix, optimized for Cloudflare Pages.Environment: Use the cloudflare adapter for server-side rendering (SSR) and edge functions.CI/CD: Automated deployments should trigger on every push to the main branch via Cloudflare Pages integration.2. Database & Persistence (Cloudflare D1 & KV)Primary Database: Use Cloudflare D1 (SQL) for relational data:Users, Orders, Products, and Ratings.Caching/Sessions: Use Cloudflare KV for:User session tokens.Temporary shopping cart data for guest users.High-speed product metadata caching.3. Media & Assets (Cloudflare R2)Image Hosting: All high-resolution fashion imagery for KTMDRIP must be stored in Cloudflare R2.Optimization: Utilize Cloudflare Images for dynamic resizing, WebP/AVIF delivery, and watermarking to ensure the "Drip" visuals load instantly on mobile.Uploads: Implement signed URLs for secure admin uploads of new products directly to R2.4. Backend Logic (Cloudflare Workers)Edge Functions: Move heavy logic (Payment validation, Auth checks, Inventory updates) to Cloudflare Workers to minimize latency.Security: Implement Cloudflare WAF (Web Application Firewall) rules to protect against bot traffic and common web exploits.5. Coding StandardsTypeScript: Strict type checking is mandatory for all Cloudflare bindings (D1, R2, KV).Wrangler: Use wrangler.toml for local development and secret management.Error Handling: Implement robust logging using Cloudflare Observatory to track edge function failures.6. Integration RequirementsStripe/Payment: Use the Stripe Node.js library compatible with the Workers runtime (no Node.js built-ins that break on the edge).Auth: Prioritize Cloudflare Access for Admin Dashboard protection or integrate with a provider like Clerk or Auth0 configured for edge runtimes.Note to Agent: Always verify compatibility with the Cloudflare Workers runtime before introducing external NPM packages. Avoid packages that rely on fs, path, or crypto (standard Node.js libs) unless they have edge-compatible alternatives.
